# HEALium backend

Server side of HEALium: data model, authentication and the server actions the
dashboard calls. Built with [Payload CMS](https://payloadcms.com) on Next.js.

## Runtime status

- **The local preview (`npm run dev` in the repository root) does not use this
  folder.** It runs the dashboard with a backend implementation that stores nothing.
- The backend was provisioned on **Figma Make**. `src/payload.config.ts` uses
  `buildFigmaConfig` from `@payloadcms/figma`, which supplies the database, file
  storage and secrets from that platform's environment (`FIGMA_*` variables). Without
  that environment the backend does not start.
- **To self-host**, replace `buildFigmaConfig` with Payload's `buildConfig`, add a
  database adapter and a `PAYLOAD_SECRET`, and remove `figma-image-loader.ts` from
  `next.config.ts`. The collections, access rules and server actions do not depend on
  Figma and stay unchanged.
- After the restructuring of the repository this folder was verified by type-checking
  (`pnpm typecheck`) only. It was **not run against a live database**, because that
  requires the platform environment.

```bash
cd backend
pnpm install
pnpm typecheck
pnpm dev          # needs the platform environment described above
```

## Structure

```
backend/
├── next.config.ts            Next.js configuration (build root = repository root)
├── tsconfig.json             Path aliases: @/* -> src/*, @dashboard/* -> ../src/*
└── src/
    ├── payload.config.ts     Registers collections and the admin panel
    ├── payload-types.ts      Generated by Payload – do not edit
    ├── collections/          Data model + access rules (one file per collection)
    ├── actions/              Server actions = implementation of BackendActions
    ├── lib/                  Payload client, session handling, queries
    └── app/
        ├── (frontend)/       Server-rendered dashboard page
        └── (payload)/        Admin panel, REST and GraphQL routes – generated, do not edit
```

The dashboard UI itself is not in this folder. It lives in `../src` and is imported
through the `@dashboard/*` alias, so the local preview and the server render exactly
the same components.

## Data model

| Collection              | Purpose                                   | Read                 | Write                         |
| ----------------------- | ----------------------------------------- | -------------------- | ----------------------------- |
| `users`                 | Crew-member accounts (dashboard sign-in)  | Own profile          | Register: anyone · change: own |
| `admins`                | Operators of the admin panel              | Admins               | Admins                        |
| `daily-health-checkins` | Morning / evening check-in answers        | Owner                | Create: signed-in user        |
| `journals`              | Private journal entries                   | Owner                | Owner                         |
| `reminder-completions`  | Completion state per reminder and user    | Owner                | Owner                         |
| `emergency-snapshots`   | Archive of emergency events               | Public (prototype)   | Admins                        |
| `media`, `folders`, `tags` | Payload media library                  | Public               | Payload defaults              |

Admins can read all collections through the admin panel.

Server-owned fields (`owner`, `astronautCode`, `completedAt`, `measuredSleepMinutes`,
`researchBasis`) are set in `beforeValidate` hooks; values sent by a client are
overwritten.

## Server actions

All actions are defined by the `BackendActions` interface in
`../src/services/backend/contract.ts`.

| File                  | Actions                                                                 |
| --------------------- | ----------------------------------------------------------------------- |
| `actions/auth.ts`     | `getPrivateDashboardData`, `registerAstronaut`, `loginAstronaut`, `logoutAstronaut` |
| `actions/journal.ts`  | `saveJournalEntry`, `deleteJournalEntry`                                |
| `actions/reminders.ts` | `setReminderCompleted`                                                 |
| `actions/check-in.ts` | `submitDailyCheckIn`                                                    |
| `actions/index.ts`    | `serverBackend`: all of the above as one object for `<BackendProvider>` |

Conventions:

- Input is validated on the server, whatever the client checked before.
- Database calls use `overrideAccess: false` together with the acting `user`, so the
  collection access rules always apply.
- Actions return `{ success, … }` objects and do not throw to the client.

## Authentication

`lib/app-auth.ts` signs crew members in through Payload and stores the JWT in an
http-only, same-site cookie (`app-session`, 7 days). Only documents of the `users`
collection are accepted as crew members; admin accounts are a separate collection.

## Emergency flow on the server host

The dashboard opens the emergency flow at `/emergency/index.html`. The local preview
serves it from `../emergency`. To offer it from this host as well, copy that folder to
`backend/public/emergency/`.

## Simulated elements

`measuredSleepMinutes` (fixed value), `astronautCode` (always `MC-01`) and the
emergency snapshots (demo records) are simulated; see
[../docs/simulated-data.md](../docs/simulated-data.md).
